HOSAPPOINT — GROUP B UI/UX ASSIGNMENT
======================================

WHAT THIS PROJECT DOES
- Login screen with basic email/password validation (demo only).
- Patient dashboard and appointment counters.
- Doctor listing with search, specialty filter, and gender filter.
- Appointment booking form with required-field validation and date validation.
- Confirmation page with a generated reference number.
- Appointment details page and My Appointments list.
- Responsive layout for desktop, tablet and mobile.
- Appointment requests are saved in browser localStorage; demo login uses sessionStorage.

HOW TO RUN
1. Extract the ZIP file into a folder.
2. Open index.html in a modern browser (Chrome, Edge, Firefox).
3. Enter any valid email and a password of at least 4 characters.
4. Open View doctors, select filters if needed, then click Book appointment.
5. Complete the form and submit. Open My appointments to view saved requests.

FILES
- index.html : page structure and interface sections
- style.css  : visual styling and responsive layouts
- script.js  : navigation, filtering, form validation and demo booking logic

IMPORTANT LIMITATIONS
- This is a front-end classroom prototype, not a real hospital system.
- Login is not connected to a server and does not authenticate real users.
- No real doctors' schedules are checked; sample doctors and time options are for demonstration.
- Appointment requests are stored only in the current browser on this device.
- No email, SMS, payment, medical record system, or hospital confirmation is connected.
- Do not enter real medical or other sensitive personal information.

ASSIGNMENT ALIGNMENT
Group B: Hospital Appointment Booking System.
Required journey: Login → Dashboard → View Doctors → Select Doctor → Book Appointment → View Appointment Details.
Included screens: Login, Patient Dashboard, Doctor Listing, Appointment Booking Form, Confirmation, Appointment Details.
The brief also asks for user research/problem definition, ideation and paper sketches, Figma prototype, a short report, screenshots and a working demonstration. The code addresses the web-interface development portion; it does not replace those other deliverables.
